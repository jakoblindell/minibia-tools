### Minibia-tools

`minibia-tools.html` (the World Compendium page) loads `data/derived/compendium.json` and `data/icons.json` at runtime, plus the per-floor spawn map terrain images (`data/derived/minimap-z*.png`).

#### Updating game data

1. Update the raw sources in `data/raw/`:
   - `library.json` — monsters, items, npcs, spells, runes, achievements. Exported manually (the Library page is Cloudflare-gated), so there's no fetch script for it — replace it by hand when you have a fresh export.
   - `monster-spawns.json` — spawn point clusters. Fetch a fresh copy with `python scripts/fetch-live.py` (also refreshes `npc-trades.json`, `definitions.json`, `npc-poi.json`, `constants.json` and `minimap.bin`).
   - `minimap.bin` — the client's raw minimap, used for the Spawn Map tab's terrain. Also refreshed by `fetch-live.py`.
2. Regenerate the derived data, in this order:
   ```
   python scripts/gen-minimap.py            # minimap.bin -> data/derived/minimap-z*.png + minimap.meta.json
   python scripts/build-data.py             # data/raw/*  -> data/derived/compendium.json (+ merchant.json, CHANGELOG.md)
   python scripts/gen-floor-plausibility.py # appends a floor bitmask to every spawnMap point (needs the two above)
   python scripts/gen-floor-connections.py  # detects stairs/ladders/holes and guesses which floor(s) each connects to (needs the two above)
   python scripts/gen-known-floors.py path/to/tibia-export.json  # optional: known spawn floors from a real-Tibia spawn export (see below)
   ```
3. Commit `data/raw/` and `data/derived/` (and the updated `CHANGELOG.md`). GitHub Pages picks it up — no other build step.

`build-data.py` also writes `data/derived/merchant.json` (for a merchant-ledger page this repo doesn't have yet) and `.js` twins of both (`window.__MINIBIA_COMPENDIUM__ = ...` etc., for loading via `<script src>` instead of `fetch()` when a page needs to work over `file://`). `data/raw/npc-trades.json` and `data/raw/definitions.json` are currently empty placeholders (`{}`) — `build-data.py` requires them to exist, but nothing here reads `merchant.json` yet.

`scripts/gen-floor-plausibility.py` (not one of the original 4 scripts — added to restore the "Hide implausible floors" toggle, which the switch to raw-cluster spawn data had silently turned into a no-op) computes, per spawn point, which of the 16 floors are plausible from the terrain alone — void detection, then a walkability classification derived from the client's `.dat` minimap-color/not-walkable data (`BLOCKING_IDX` in the script), checked over a window around the point rather than a single pixel. It appends the result as a 4th element to each `spawnMap` point (`[x, y, count, floorMask]`); a point with no confident floor falls back to plausible-everywhere rather than guessing wrong. See the script's docstring for the full algorithm.

`scripts/gen-floor-connections.py` (also not one of the original 4 - added for the map's "Stairs & holes" layer and the pathfinder) finds every tile the minimap draws as a stairs/ladder/hole/ropehole (a flat yellow - but the same yellow also paints some roofs and ground, so only staircase-sized patches of up to 12 tiles that aren't rings count; that skips ~20,000 roof/ground tiles and leaves ~14,300 markers) and works out which adjacent floor each connects to, purely from the terrain. Each marker tile goes one way only (up or down, never both) and pairs with the marker directly above/below it, preferring the best shape match - a 3-wide staircase pairs with the 3-wide one under it, not a 1-tile stair it touches - else one within 2 tiles that isn't already going the same way. Pairing is per tile, so an up and a down stair side by side in one yellow patch stay separate. A column of identical markers splits into stacked pairs from the top down, which is how ladder towers alternate ladder and hole; a plain walkable-vs-void asymmetry with no marker is a weaker guess, a light grey tile sitting exactly on top of a yellow marker that isn't itself going down is the top of a stairs/trap door (the minimap only draws the arrival end yellow for those - ~370 in this snapshot), a marker with nothing walkable on either neighbouring floor is a dead end (dropped - the decorative/blocked holes the client also draws yellow, ~6%), and anything still ambiguous is written to a separate `floorConnectionsUnknown` list instead of guessed (~2% of markers, in this snapshot). The World Compendium page can step through that unknown list and let a human call each one by eye - see "Hidden map tools" below - and export the answers as JSON; drop that file at `data/raw/floor-connection-labels.json` and rerun this script to fold them in as confirmed, overriding the algorithm. See the script's docstring for the full method.

The same script also writes `data/derived/door-candidates.json`, the possible doors the Find path tool uses: every tile of 1-thick grey or red wall whose two opposite walkable sides fall in different 4-connected areas of that floor. Walls you could just walk around never qualify, so a route never cuts through one needlessly.

Monster cards have a **Hunting** section, computed in the browser from data already in `compendium.json`: expected loot weight per kill (each sellable drop's chance × average quantity × the item's weight - empty bags and unsellable junk don't count) and gold per oz, gold and XP per 100 HP dealt, and spawn clustering from the `spawnMap` points - total spawns, hunting areas (spawns chained no more than 25 tiles apart, on a shared plausible floor), and the best spot (most of that monster within 12 tiles of one point, with a map link and who else spawns there). Loot rows show each item's weight and gp/oz. The monster list can be sorted by all of these (gold per oz, lightest loot, gold/XP per 100 HP, best spot, best spot value, biggest hunting area, spawns in world).

On the Spawn Map, clicking (or tapping) anywhere that isn't a floor-connection marker copies that tile's coordinates, e.g. `x32480 y31644 z10`; the readout next to the map buttons shows the tile under the cursor.

`scripts/gen-known-floors.py` deduces which floor our spawn clusters are on from a real-Tibia monster-database export (JSON with `"monster": {"name"}` and `"spots": [{"spawns": [{"x","y","z"}]}]` blocks). Minibia's world is largely the real Tibia map, so a cluster with real spawns of the same monster within 8 tiles takes their floor(s) - only floors the terrain check (`gen-floor-plausibility.py`) already allows, nearest first; monsters match by name, plus a few aliases for Minibia renames (Beholder = Bonelord...). The export itself isn't kept in the repo - only the small result, `data/derived/known-floors.json` (`{"radius", "monsters": {name: [[x, y, floorMask], ...]}}`). On the current export: 10,989 of the 15,226 spawn clusters of the 272 matching monsters got a known floor (9,194 a single floor); the rest are Minibia-only areas/monsters. The Spawn Map's **Real-Tibia floors** toggle (on by default) shows those clusters only on their floor, with a white ring and the floor in the tooltip, and monster cards show a per-floor count.

#### Map tools

The Spawn Map tab is one workspace: the map with a mode switch above it - **Spawns**, **Find path**, **Route builder** - and a side panel (below the map on narrow screens) for the current mode. The floor control and the cursor's coordinates sit on the map; **Layers** holds the display toggles (Real-Tibia floors, Hide implausible floors, Stairs & holes). In Spawns mode the side panel has the difficulty filter and, under **Data tools**, the curation tools.

- **Stairs & holes** (layer) - draws `floorConnections` on the current floor and lets you click a marker to jump to whichever floor it resolves to; ones labeled both ways by hand don't jump, since there's nothing to disambiguate which one you meant.
- **Find path** (mode) - click a start point, then an end point (switch floors in between if needed), and it draws a walking route. Walkability is decoded in the browser from the same terrain PNGs the map draws (1 bit per tile per floor), blocked by the same color table as the floor-plausibility filter, and floors only connect through `floorConnections` stairs/ladders/holes - never by walking over unwalkable tiles. The search is Jump Point Search A* in a Web Worker: the first use spends a few seconds decoding all 16 floors, then routes typically take milliseconds. The minimap draws most doors as plain wall, so a 1-tile-thick grey or red wall with walkable ground on both sides that are otherwise unconnected counts as a possible door (`door-candidates.json`, below). The route may pass through one, at a higher cost than walking around. Every one it uses is counted in the status line and marked with a white square on the map, so you can check it's a real door. It can't know about boats, teleports, or tiles the color table misjudges, so "no route" between islands is expected.
- **Route builder** (mode) - click out waypoints (switching floors between clicks as needed); each leg between two points follows the pathfinder's walking route, or a dashed straight line if it can't find one. Add a title, a note per point, and optionally loop back to the start. The whole route is packed into the URL (`#route=...`, base64 JSON - no server or storage), so "Copy share link" gives a link anyone can open: opening a shared link shows the route read-only, with "Edit a copy". Titles and notes from a link are only ever rendered as text.
  - **Cave bot route** (in the Route builder panel) - every route point is also a waypoint for the cave bot's Cave → Route "Import JSON" format: pick its type (walk, stand, wait, use, rope, shovel, magic rope, stairs up, hole/stairs down, ladder up, drop item, depot, NPC, label, go to label, supply check) and its settings with the ⚙ button (common params as fields, everything else as raw params JSON). **Fill in bot waypoints** expands the route along the computed walking path: a walk waypoint every N tiles and a floor-change waypoint at every stairs/hole/ladder it takes, placed on the tile you stand on before the step with the step direction filled in (going up defaults to stairs-up - the minimap can't tell stairs, ladders and rope spots apart, so change those rows if needed). **Copy bot JSON** / **Download .json** export `{ "version": 1, "route": [...] }` (no `settings`, which would overwrite the character's Cave settings), after checking the same things the bot's importer rejects (duplicate labels, a label waypoint without a label, goto/supply-check targets that don't exist, buy-item without an item, sell-items without rows, drop-item without an item, bad directions/modes). **Import bot JSON** takes a pasted route - the bot's own Copy output, or a bare array of waypoints - and maps it out (following each leg with the pathfinder; the bot's `settings` only set whether it loops, and never go into exports). Imported waypoints keep every param the bot wrote, so exporting gives back the same route; share links leave out the bot's default param values and restore them on open. Bot fields also ride along in the share link. Waypoints are colour-coded by type on the map and in the list (with a colour key), can be dragged to a new tile while editing (clicking one opens its settings), and floor-change waypoints are checked against the detected stairs/holes/rope spots: hole/stairs down needs a "down" marker on or next to its tile, stairs/ladder up and rope an "up" marker, magic rope one on the exact tile (or on the tile its direction points at), and the next waypoint must be one floor down/up - ✓ when it matches, ? when only an unresolved marker is there, and ⚠ plus a red ring on the map when nothing is, so it's possibly misplaced.
- **Preview a Tibia export** (Data tools) - preview a different real-Tibia spawn export without regenerating: load (or paste) - one monster or a whole multi-monster file, anything with `"monster": {"name"}` and `"spots": [{"spawns": [{"x","y","z"}]}]` - and it matches each monster to ours by name: a spawn cluster with real spawns of the same monster within the match radius (default 8 tiles) takes their floor, as long as our terrain allows that floor there (nearest floors win). Matched clusters then show only on their floor, with a white ring, their tooltip names the floor, and monster cards show a per-floor count; a table lists coverage per monster. Runs entirely in the browser, for this visit only (it replaces the built-in known floors until you clear it); the small result can be downloaded. On Crypt Shamblers: 117 of 172 clusters matched (106 to a single floor); every matched floor was one the terrain check already allowed.
- **Label unresolved stairs** (Data tools) - opens a small floating panel and steps through `floorConnectionsUnknown` one at a time (jumping the map to each), letting you call each Up/Down/Unknown by eye. Answers save to this browser's `localStorage` as you go (survives a reload) and "Export JSON" downloads them in the format `gen-floor-connections.py`'s manual-override loader expects.

`scripts/build-bundle.py` packages multiple tool pages (`site/index.html`, `merchant-ledger.html`, `compendium.html`, `accounts.html`) plus the minimap PNGs into a single self-contained `dist/minibia-tools.html`. It's kept here for reference but isn't wired up — this repo only has the one compendium page, served directly via GitHub Pages rather than bundled.

`data/icons.json` (item icon images, keyed by item id) isn't part of this pipeline and is updated separately.

Because the page fetches JSON at runtime, it needs to be served over HTTP (e.g. GitHub Pages, or `python3 -m http.server` locally) rather than opened directly as a `file://` URL.
